# Сервис уведомлений

Автор: Покаташкин Владимир Иванович

## Что делает программа

Сервис отправки уведомлений. 2 способа - email и push.

## Как запустить

Выполнение из папки student

Версия Go - 1.26

Запуск main - go run ./cmd/notify

Запуск тестов - go test ./practice

## Проверенные случаи

результат успешной отправки - в обеих историях сообщений появилось новое - "Заказ принят"

результат отправки пустого текста - Dispatch возвращает обёртку над ErrEmptyMessage на первой итерации, истории сообщений не изменяются

результат отправки сообщения с помощью push-notifier'a без device id - Dispatch возвращает обёртку над &SendError, истории не меняются

результат отправки сообщения с помощью BrokenNotifier - SafeDispatch кладёт в возвращаемый слайс обёртку над ErrNotifierPanic, в истоию исправного push-notifier'a добавляется сообщение "schemotechnique" (отправление отработало без ошибок)


## Обработка ошибок

Dispatch прекращает работу на первой ошибке и возвращает обёртку над ней, не обрабатывает панику. SafeDispatch возвращает слайс ошибок, не прекращает работу при ошибке у одного из notifier'ов, при панике в слайс ErrNotifierPanic

errors.Is используется в main() для обработки пустого сообщения, errors.As - там же для получения ошибки SendError

recover находится внутри defer - потому что паника поднимается вверх по стеку, выполняя только блоки defer в каждой функции. если поместить recover вне defer, recover не отработает и программа завершится аварийно.
Внутри SafeSend, чтобы паника одного канала не отменяла работу остальных.
